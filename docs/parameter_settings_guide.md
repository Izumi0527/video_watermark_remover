# 参数设置（右侧面板）四大模块如何设置

本文档面向“主窗口右侧的参数设置面板”，按 4 个标签页说明每个参数应如何选择与调节，并给出常见问题的调参顺序。

适用范围：本仓库当前 UI（`检测参数 / 修复参数 / 性能参数 / 输出参数` 4 个标签页）。

---

## 0. 快速结论（推荐调参顺序）

1. 先调 **检测参数**：确保水印能被稳定检出且误检可控。
2. 再调 **修复参数**：在可接受耗时内拿到更自然的修复效果。
3. 需要提速时再调 **性能参数**：优先保证稳定，不要为了速度牺牲正确性。
4. 最后调 **输出参数**：根据交付需要选择格式、压缩、命名、音频保留。

---

## 1. 检测参数怎么设

检测参数决定“能不能找到水印、找到的框是否干净”。这里的核心是：**敏感度与最小区域**。

### 1.1 检测敏感度（UI：0.10 到 1.00）

作用：控制 YOLO 检测的置信度阈值（越低越敏感）。

建议：

- 水印漏检：把敏感度适当 **调低**（例如 `0.50 → 0.35 → 0.25`）。
- 误检太多：把敏感度适当 **调高**（例如 `0.25 → 0.35 → 0.45`）。

经验区间（仅供起步）：

- 专用水印模型场景：通常 `0.25-0.35` 更容易覆盖边缘与透明水印。
- 通用模型/复杂背景误检多：可以从 `0.45-0.60` 起步。

### 1.2 检测方法（auto / GPU / CPU）

作用：选择 YOLO 推理运行设备。

建议：

- 默认用 `auto`：可用时优先 GPU，不可用则自动回退 CPU（最稳妥）。
- 只有在你明确确认 CUDA 环境正常时，才建议强制 `GPU`。
- 机器没有 GPU 或 GPU 不稳定时，用 `CPU`。

### 1.3 最小检测区域（像素）

作用：过滤非常小的检测框，减少噪点进入掩码，降低误伤与修复负载。

建议：

- 噪点误检多：适当 **增大**（例如 `100 → 200 → 400`）。
- 小水印总漏掉：适当 **减小**（例如 `100 → 50`）。

### 1.4 预处理选项（模糊/锐化/降噪）

建议：

- 背景很花且误检多：优先尝试开启“降噪”，必要时再开启“模糊”。
- 水印边缘很细、对比度低：可以尝试开启“锐化”，但可能带来误检上升。

### 1.5 掩码优化（收缩 / 静态水印跟踪）

建议：

- 误伤明显：开启“掩码收缩”，并从小强度开始（例如 `1-2px`）。
- 视频为静态角标水印：可开启“静态水印跟踪”，并设置合理间隔（例如 `3-5` 帧）。
- 水印随画面运动明显：不建议开启跟踪，或把间隔调小。

补充：

- YOLO 的 bbox→mask 还有一组“边界精修”参数在 `config.ini` 中配置（padding 与闭运算），详见：
  - [yolo_mask_refine_params.md](./yolo_mask_refine_params.md)

## 2. 修复参数怎么设

修复参数决定“修得像不像”。核心是：**修复算法、质量等级、后处理**。

### 2.1 修复算法（LaMa / 兼容 U-Net / TELEA / Navier-Stokes / 自定义）

建议：

- 追求效果：优先 `LaMa 深度学习修复`（通常更自然，但更慢、依赖权重与算力）。
- 追求速度：小水印可用 `TELEA`（快），效果不够再试 `Navier-Stokes`。
- 兼容路径：`兼容 U-Net` 主要用于旧模型/兼容验证，不建议当作首选生产路径。

### 2.2 修复半径（1-10）

说明：主要影响 OpenCV 修复算法的传播范围（半径越大，影响范围越大）。

建议：

- 水印边缘有明显“圈边”或残留：适当增大（例如 `3 → 5`）。
- 误伤扩散明显：适当减小（例如 `5 → 3 → 2`）。

### 2.3 修复质量（1-5）

建议：

- 质量越高通常越慢，但伪影更少。
- 通用起步：`3`，效果不够再升到 `4-5`。

### 2.4 后处理（平滑 / 混合 / 增强）

建议：

- 画面边缘不自然：开启“边缘平滑”。
- 修复区域颜色突兀：开启“颜色混合”。
- 画面整体偏糊：可尝试“图像增强”，但可能引入锐化噪点。

### 2.5 混合修复（提速）

适用：画面中水印较多，但大多数是“小块角标/文字”的场景。

建议：

- 开启“混合修复”后：小水印走 OpenCV，大水印仍走深度修复。
- “小水印阈值”建议从 `0.30%` 起步，根据素材调整：
  - OpenCV 痕迹明显：适当降低阈值（让更多区域走深度修复）。
  - 速度仍然慢：适当提高阈值（让更多区域走 OpenCV）。

## 3. 性能参数怎么设

性能参数决定“跑得快不快、稳不稳”。核心是：**处理模式、并行度、显存与缓存、批处理策略**。

### 3.1 处理模式（单进程 / 多进程分块 / 流水线）

建议：

- 首选“单进程”：稳定、便于定位问题。
- “多进程分块”：适合 CPU 或 IO 较强场景，能提升吞吐，但更吃资源。
- “流水线”：适合长视频与批处理，整体吞吐好，但对缓存与内存更敏感。

### 3.2 并行度（0=自动，1-16）

建议：

- 默认 `自动`（0）最稳。
- 如果机器核心数多、资源充足再手动增大；出现卡顿/爆内存时及时回退。

### 3.3 启用深度修复（GPU）与显存限制

建议：

- 只有在确实要用深度修复后端时再打开（且需要 CUDA/权重）。
- 显存吃紧或容易 OOM：适当降低“GPU 内存限制”。

### 3.4 缓存与批处理策略

建议：

- 批处理并发不要一上来拉满：先从 `1-2` 起步，确认稳定后再提高。
- “失败自动重试/重试次数”适合不稳定环境，但会增加总耗时。

## 4. 输出参数怎么设

输出参数决定“怎么交付文件”，不会改变检测与修复逻辑本身。

### 4.1 输出格式

说明：一般 **仅图片**生效；视频输出通常保持原容器或由导出策略决定。

建议：

- 不确定时用“保持原格式”。
- 需要更小体积可选 `JPG`，需要无损可选 `PNG`（体积更大）。

### 4.2 压缩质量（1-100）

建议：

- 通用 `85%` 起步。
- 画质优先可提高；体积优先可降低。

### 4.3 文件名与音频

建议：

- “添加处理后缀”建议开启，避免覆盖原文件。
- 视频需要保留配音/背景音：开启“保留原始音频”。

## 5. 本次 UI 文案精简与横向滚动优化说明

问题背景：

- 右侧参数面板存在较长说明文本与较长下拉选项，容易撑宽布局，触发横向滚动条与“左右虚拟滚轮”。

本次处理策略：

- 将过长说明收敛为短句，把细节放到 `tooltip`（鼠标悬停可查看）。
- 对提示 `QLabel` 启用自动换行（`WordWrap`），减少横向撑宽。
- 禁用右侧滚动区域的横向滚动条，并对关键下拉框启用“最小内容宽度”策略，降低横向滚动出现概率。
