## 检测参数功能

### 功能评级：★★★★★ (核心功能)

检测参数决定了系统能否准确找到水印的位置和范围，是整个水印去除流程的第一步，直接影响后续修复效果。

### 参数详细说明

#### 1. 检测敏感度 (0.1 - 1.0)

**技术原理**：控制 YOLO 模型的置信度阈值 (`conf_threshold`)

| 敏感度值 | 检测行为 | 适用场景 | 优缺点 |
|---------|---------|---------|--------|
| **0.1 - 0.3** | 极度敏感 | 水印非常模糊/半透明 | ✅ 漏检少 ❌ 误报多 |
| **0.4 - 0.6** | 平衡模式 | 一般场景（推荐） | ✅ 平衡误报和漏检 |
| **0.7 - 1.0** | 保守模式 | 水印清晰且明显 | ✅ 误报少 ❌ 可能漏检 |

**对水印去除的帮助**：
- ✅ **准确定位水印**：合适的敏感度能准确框选水印区域
- ✅ **减少误报**：过高的敏感度会将正常图像内容误识别为水印
- ✅ **避免漏检**：过低的敏感度会漏掉部分水印

**推荐值**：`0.5` (平衡模式)

**实际案例**：
```
场景1: 透明度50%的水印 → 建议敏感度 0.3-0.4
场景2: 纯色不透明水印 → 建议敏感度 0.5-0.6
场景3: 复杂背景下的水印 → 建议敏感度 0.6-0.7
```

本项目提供 **3种YOLO检测方法**，本质上是同一个YOLO v11x模型在不同硬件设备上的运行模式：

|------|----------|---------------|-------------|----------|
| **模式1** | `YOLO v11x 深度学习auto (推荐)` | `auto` | 自动检测：优先GPU，回退CPU | **通用场景**（推荐） |
| **模式2** | `YOLO v11x GPU 加速` | `cuda` | 强制使用GPU | 确认有GPU且需要极致性能 |
| **模式3** | `YOLO v11x CPU 模式` | `cpu` | 强制使用CPU | 无GPU或GPU故障时 |

##### 🔍 模式1: YOLO v11x 深度学习auto (推荐)

**技术实现** (`yolo_detector.py:68-72`):
```python
if device is None:  # device="auto"时传入None
    self.device = "cuda" if torch.cuda.is_available() else "cpu"
else:
    self.device = device
```

**工作原理**：
1. 首先检测系统是否安装CUDA及GPU驱动 (`torch.cuda.is_available()`)
2. 如果检测到可用GPU → 自动使用GPU加速
3. 如果未检测到GPU → 自动回退到CPU模式
4. **智能切换**：GPU显存不足时不会崩溃，而是优雅降级

**优点**：
- ✅ **智能适配**：自动选择最优硬件，无需用户手动判断
- ✅ **容错性强**：GPU故障时自动回退CPU，保证程序稳定运行
- ✅ **开箱即用**：默认配置，适合大多数用户

**缺点**：
- ⚠️ **不透明**：用户不清楚当前使用的是GPU还是CPU（可通过日志查看）

**适用场景**：
- ✅ 不确定系统GPU配置的用户
- ✅ 需要在多台电脑间迁移配置的场景
- ✅ 追求稳定性优先于极致性能的场景

**日志输出示例**：
```

2025-12-07 15:08:11 - YOLOWatermarkDetector v2.0 initialized
  - Device: cpu
```

##### ⚡ 模式2: YOLO v11x GPU 加速

**技术实现** (`ai_params_builder.py:283-284`):
```python
if "GPU" in detection_method or "gpu" in detection_method.lower():
    return "cuda"  # 强制使用GPU
```

**工作原理**：
1. 直接将模型加载到GPU (`model.to("cuda")`)
2. 所有推理计算在GPU上执行（包括预处理、推理、后处理）
3. **不进行CPU回退**：如果GPU不可用会直接报错

**优点**：
- ✅ **性能最优**：100%使用GPU并行计算能力
- ✅ **批处理优势**：视频处理时GPU批量推理效率极高
- ✅ **显存优化**：内置显存监控机制 (`gpu_monitor.py`)，自动调整批大小防止OOM

**缺点**：
- ❌ **硬件依赖**：必须有NVIDIA GPU + CUDA环境
- ❌ **显存需求**：至少需要 4GB 显存（推荐 8GB+）
- ❌ **无容错**：GPU故障时程序会崩溃

**适用场景**：
- ✅ 确认系统有可用GPU（NVIDIA RTX 2060及以上）
- ✅ 需要处理大量视频或高分辨率图片
- ✅ 追求极致处理速度的专业用户

**性能对比**（NVIDIA 4070 Ti Super）：
```
单张1080p图片:  CPU ~2秒    vs  GPU ~0.3秒   (6-7倍提升)
视频10秒60fps:  CPU ~120秒  vs  GPU ~15秒    (8倍提升)
批量100张图片: CPU ~200秒  vs  GPU ~30秒    (6-7倍提升)
```

**GPU显存自适应机制** (`yolo_detector.py:284-300`):
```python
# 根据可用显存自动调整批大小
safe_batch_size = get_safe_batch_size(self.batch_size, frame_size)
if safe_batch_size < len(frames):
    # 分批处理，避免OOM
    for i in range(0, len(frames), safe_batch_size):
        batch = frames[i:i + safe_batch_size]
        ensure_gpu_memory(min_free_mb=300)  # 确保至少300MB空闲显存
        results = model(batch, device="cuda")
```

##### 💻 模式3: YOLO v11x CPU 模式

**技术实现** (`ai_params_builder.py:285-286`):
```python
elif "CPU" in detection_method or "cpu" in detection_method.lower():

```

**工作原理**：
1. 模型完全运行在CPU上，使用多核并行计算
2. 推理速度取决于CPU性能（核心数、主频、缓存）
3. **不使用GPU**：即使系统有GPU也不会调用

**优点**：
- ✅ **兼容性强**：任何电脑都能运行，无需GPU
- ✅ **稳定可靠**：不依赖GPU驱动，避免CUDA版本问题
- ✅ **调试友好**：CPU模式更容易定位问题

**缺点**：
- ❌ **速度慢**：处理速度比GPU慢 3-10 倍
- ❌ **资源占用**：CPU占用率高（可能影响其他程序）

**适用场景**：
- ✅ 无GPU的电脑（集成显卡、AMD显卡）
- ✅ GPU驱动有问题或CUDA环境配置失败
- ✅ 处理少量图片（1-10张）且不急于时间
- ✅ 调试和测试阶段

**CPU多线程优化**：
虽然YOLO模型推理本身在CPU上较慢，但本项目通过 **多线程并行处理** (`performance_params.thread_count`) 可以部分缓解：

##### ⚠️ 常见问题与解决方案

**Q1: 选择"GPU 加速"但程序崩溃？**
- **原因**: GPU不可用或CUDA环境问题
- **解决**: 切换到"深度学习(推荐)"或"CPU模式"
- **检查**: 运行 `nvidia-smi` 检查GPU状态，查看日志中的device信息

**Q2: "深度学习(推荐)"模式实际运行在CPU上？**
- **原因**: 未检测到可用GPU (torch.cuda.is_available() = False)
- **解决**: 安装PyTorch GPU版本: `pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118`
- **验证**: Python中运行 `import torch; print(torch.cuda.is_available())`

**Q3: GPU模式显存不足（OOM错误）？**
- **解决方案1**: 降低"性能参数"中的GPU内存限制（默认2048MB → 降至1024MB）
- **解决方案2**: 减少批处理大小（config.ini中的batch_size）
- **解决方案3**: 切换到CPU模式处理

**Q4: 三种模式检测准确率一样吗？**
- **答案**: ✅ **完全一样**。三种模式使用同一个YOLO模型文件(`yolo11x-watermark.pt`)，只是运行设备不同。
- **差异**: 仅影响 **处理速度**，不影响 **检测准确率** 和 **检测结果**

#### 3. 最小检测区域 (1 - 10000 像素)

**技术原理**：过滤掉面积小于指定像素数的检测结果

**对水印去除的帮助**：
- ✅ **避免噪点误检**：过滤掉图像噪点、JPEG压缩伪影
- ✅ **忽略小图标**：避免将按钮、图标等误识别为水印
- ⚠️ **注意小水印**：设置过大会导致真正的小水印被忽略

**推荐值**：`100 像素`

**计算公式**：
```
最小区域 = √(宽度 × 高度)
示例: 10×10 像素的水印 = 100 像素面积
```

## 修复参数功能

### 功能评级：★★★★★ (核心功能)

修复参数决定了去除水印后的画面质量，直接影响用户对处理结果的满意度。

### 参数详细说明

#### 1. 修复方法

本项目支持 **5种修复算法**，各有优劣：

| 方法 | 速度 | 小水印效果 | 大水印效果 | 复杂背景 | 硬件要求 | 推荐场景 |
|------|------|------------|------------|----------|----------|----------|
| **GPU 深度学习 U-Net** | ★★★☆ | ★★★★ | ★★★★★ | ★★★★★ | 需GPU | 复杂背景、大面积水印 |
| **TELEA 快速修复** | ★★★★★ | ★★★★★ | ★★★☆ | ★★★☆ | 仅CPU | 小水印、快速处理 |
| **Navier-Stokes 高质量** | ★★★☆ | ★★★★ | ★★★★ | ★★★★ | 仅CPU | 需要保持边缘的场景 |
| **自定义插值方法** | ★★★★★ | ★★★★★ | ★★☆☆ | ★★☆☆ | 仅CPU | 小型半透明水印 |
| **自动选择模式 (Auto)** | 自适应 | ★★★★ | ★★★★ | ★★★★ | 仅CPU | 通用场景（推荐） |

**对水印去除的帮助**：
- ✅ **视觉效果**：不同算法修复后的自然度、模糊度、色彩还原度不同
- ✅ **场景适配**：根据水印大小和背景复杂度选择合适算法

**Auto模式智能选择逻辑**：
```python
水印面积占比 < 5%  → 使用"自定义插值"（最快）
水印面积占比 < 15% → 使用"TELEA"（平衡）
水印面积占比 ≥ 15% → 使用"Navier-Stokes"（高质量）
```

**推荐配置**：
- 有 GPU：选择 `GPU 深度学习 U-Net`
- 无 GPU：选择 `自动选择模式 (Auto)`

#### 2. 修复半径 (1 - 10)

**技术原理**：控制 OpenCV 修复算法的像素传播距离

**对水印去除的帮助**：

| 半径值 | 修复范围 | 效果 | 适用场景 |
|--------|---------|------|----------|
| **1-2** | 极小 | 边缘锐利，可能修复不完整 | 细小水印 |
| **3-5** | 适中 | 平衡细节和修复范围（推荐） | 一般水印 |
| **6-10** | 较大 | 修复彻底，但可能过度模糊 | 大型水印 |

**推荐值**：`3`

**注意事项**：
- ⚠️ 半径过大会导致修复区域过度模糊
- ⚠️ 半径过小可能无法完全覆盖水印边缘

#### 3. 修复质量 (1 - 5)

**技术原理**：影响修复算法的迭代次数和精度

| 质量等级 | 名称 | 处理时间 | 效果 | 适用场景 |
|---------|------|---------|------|----------|
| **1** | 最低 | 最快 | 可能有残留 | 快速预览 |
| **2** | 低 | 较快 | 基本可用 | 对质量要求不高 |
| **3** | 中等 | 适中 | 平衡速度和质量（推荐） | 一般使用 |
| **4** | 高 | 较慢 | 效果较好 | 对质量有要求 |
| **5** | 最高 | 最慢 | 效果最佳 | 追求极致效果 |

**对水印去除的帮助**：
- ✅ 质量越高，修复后的自然度越好
- ⚠️ 质量提升带来的速度下降呈指数级

## 修复方法深度分析

### 支持的修复方法

本项目支持 **5种修复算法**：

#### 1. GPU 深度学习 U-Net

**技术实现**：PyTorch UNetInpaintingModel
**文件位置**：`app/core/ai/dl_inpainter.py`

**模型架构**：
```
输入: (B, 4, H, W) - 3通道RGB + 1通道mask
    ↓
Encoder (4层卷积下采样)
    64 → 128 → 256 → 512 channels
    ↓
Bottleneck (1024 channels)
    ↓
Decoder (4层上采样 + skip connections)
    512 → 256 → 128 → 64 channels
    ↓
输出: (B, 3, H, W) - 3通道RGB
```

**优点**：
- ✅ 复杂背景修复效果好
- ✅ 大面积水印处理能力强
- ✅ GPU并行处理高效

**缺点**：
- ❌ 需要GPU硬件支持
- ❌ 需要预训练模型（默认随机初始化效果差）
- ❌ 显存占用较大

---

#### 2. TELEA 快速修复

**技术实现**：OpenCV cv2.INPAINT_TELEA
**文件位置**：`app/core/ai/image_inpainter.py`

**算法原理**：Fast Marching Method (快速行进法)

**优点**：
- ✅ 速度极快，适合实时处理
- ✅ 小水印修复效果优秀
- ✅ CPU友好，无硬件要求

**缺点**：
- ❌ 大区域可能出现模糊
- ❌ 复杂纹理还原能力有限

---

#### 3. Navier-Stokes 高质量修复

**技术实现**：OpenCV cv2.INPAINT_NS
**文件位置**：`app/core/ai/image_inpainter.py`

**算法原理**：基于流体动力学 Navier-Stokes 方程

**优点**：
- ✅ 边缘保持能力强
- ✅ 大区域修复效果较好
- ✅ 纹理连续性好

**缺点**：
- ❌ 速度比TELEA慢
- ❌ 复杂纹理仍有局限

---

#### 4. 自定义插值方法

**技术实现**：高斯模糊 + 权重混合
**文件位置**：`app/core/ai/image_inpainter.py:174-230`

**算法流程**：
```
1. 寻找修复区域轮廓
2. 获取边界矩形 + padding
3. 高斯模糊获得背景估计
4. 形态学膨胀创建过渡区域
5. 权重混合实现平滑过渡
```

**优点**：
- ✅ 小水印效果最好
- ✅ 过渡自然，无明显边界
- ✅ 速度最快

**缺点**：
- ❌ 大区域效果差（模糊明显）
- ❌ 无法恢复复杂纹理

---

#### 5. 自动选择模式 (Auto)

**技术实现**：根据水印面积自动选择算法
**文件位置**：`app/core/ai/image_inpainter.py:158-168`

**选择逻辑**：
```python
# 计算水印面积占比
area_ratio = 水印面积 / 图像总面积

if area_ratio < 5%:      # 小水印
    return _custom()      # 使用自定义插值（最快）
elif area_ratio < 15%:   # 中等水印
    return _telea()       # 使用TELEA（平衡）
else:                    # 大水印
    return _ns()          # 使用Navier-Stokes（高质量）
```

**推荐使用**：通用场景的最佳选择

## 常见问题FAQ

### Q1: 为什么检测不到水印？

**可能原因**：
1. 检测敏感度设置过高 → 降低至 0.3-0.4
2. 水印过于透明 → 降低检测敏感度
3. 水印面积小于最小检测区域 → 降低最小检测区域
4. 模型未正确加载 → 检查日志中的模型加载信息

**解决方案**：
1. 尝试调低检测敏感度至 0.3
2. 使用手动选择模式框选水印
3. 检查预处理选项是否启用了降噪

---

### Q2: 修复后仍有明显痕迹怎么办？

**可能原因**：
1. 修复方法不适合当前场景
2. 修复质量设置过低
3. 后处理选项未启用

**解决方案**：
1. 尝试切换修复方法（推荐 GPU U-Net 或 Auto）
2. 提高修复质量至 4-5
3. 启用"边缘平滑"和"颜色混合"后处理
4. 适当增大修复半径至 4-5

---

### Q3: 处理速度太慢怎么办？

**优化方案**：
1. 启用GPU加速（速度提升3-10倍）
2. 降低修复质量至 2-3
3. 选择 TELEA 快速修复方法
4. 禁用所有预处理和后处理选项
5. 增加处理线程数

---

### Q4: GPU加速无法启用？

**检查清单**：
1. 确认已安装 NVIDIA GPU 驱动
2. 确认已安装 CUDA 11.0+
3. 确认 PyTorch 版本支持 CUDA
4. 检查 GPU 显存是否充足（≥4GB）
5. 查看日志中的 GPU 检测信息

---

### Q5: 修复后颜色不一致？

**解决方案**：
1. 启用"颜色混合"后处理选项
2. 尝试使用 Auto 自动选择模式
3. 对于复杂背景，使用 GPU U-Net 方法
4. 适当增大修复半径，扩大修复范围

---

### Q6: 批量处理时内存不足？

**优化方案**：
1. 降低 GPU 内存限制
2. 减少处理线程数至 2-4
3. 降低缓存大小至 256MB
4. 禁用缓存功能
5. 分批次处理文件
