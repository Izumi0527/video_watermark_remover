# 处理中媒体类型文案分流设计

**目标**
- 修复图片与视频在处理中阶段都显示为“处理图片/图像中”的问题。

**根因**
- `src/app/ui/components/preview_panel.py` 的处理中提示写死为“⏳ 正在处理图像，请稍候...”。
- `src/app/ui/signal_handler.py` 在开始处理时不区分图片/视频，统一调用该提示。
- 状态栏和日志通过同一条状态链路接收泛化文案，放大了显示不分流的问题。

**方案**
- 在 `SignalHandler` 中基于文件扩展名判定媒体类型，统一生成“图片/视频”相关文案。
- 让 `PreviewPanel.show_processing_progress()` 接收外部文案，而不是内部写死“图像”。
- 单文件开始处理、批处理当前文件切换时，都按媒体类型发送状态栏/日志/预览提示。

**边界**
- 不改 AI、视频、音频处理逻辑。
- 不改处理完成后的图片区分加载逻辑。
- 优先在 UI 编排层完成修复。

**验证**
- 单元测试覆盖：图片开始处理显示“正在处理图片”、视频开始处理显示“正在处理视频”。
- 单元测试覆盖：批处理当前文件切换时按扩展名显示正确类型。
- 回归测试覆盖：状态栏与日志文案保持一致。
