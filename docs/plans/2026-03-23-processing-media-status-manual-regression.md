# 处理中媒体类型文案分流手测回归清单

**目的**
- 验证图片与视频在处理中阶段的提示文案已正确分流。
- 验证预览区、状态栏、日志面板三处文案保持一致。
- 验证单文件与批处理两条链路都不会再错误显示为“处理图片中”。

**适用范围**
- `src/app/ui/components/preview_panel.py`
- `src/app/ui/signal_handler.py`

**回归前准备**
- 准备 4 个样本文件：`1.jpg`、`2.jpg`、`1.mp4`、`2.mp4`
- 启动应用，确保可以看到以下区域：
  - 预览区处理提示
  - 状态栏
  - 日志面板
- 建议在每轮回归前清空日志面板，避免旧日志干扰判断

**通用通过标准**
- 预览区提示必须按实际媒体类型显示“图片”或“视频”
- 状态栏文案必须与当前处理媒体类型一致
- 日志面板文案必须与状态栏语义一致
- 批处理切换到下一个文件时，三处文案必须同步切换
- 处理完成后，不应残留错误的处理中媒体类型文案

---

## 场景 1：单图片处理

**操作步骤**
1. 导入 `1.jpg`
2. 点击开始处理
3. 观察处理开始后的预览区、状态栏、日志面板

**预期结果**
- 预览区显示：`⏳ 正在处理图片，请稍候...`
- 状态栏显示：`开始处理图片...`
- 日志面板出现与“开始处理图片”一致的状态提示
- 处理完成后，不应出现“视频”相关文案

---

- 处理完成后，不应残留“处理中图片”的旧文案

---

## 场景 3：批量处理，首个文件为图片

**操作步骤**
1. 批量导入 `1.jpg`、`1.mp4`
2. 点击开始批处理
3. 观察第一个文件开始处理时的三处文案
4. 等待切换到第二个文件，再次观察三处文案

**预期结果**
- 处理第一个文件时：
  - 预览区显示：`⏳ 正在处理图片，请稍候...`
  - 状态栏显示：`正在处理图片: 1.jpg`
  - 日志面板显示与状态栏一致的处理中文案
- 切换到第二个文件时：
  - 预览区显示：`⏳ 正在处理视频，请稍候...`
  - 状态栏显示：`正在处理视频: 1.mp4`
  - 日志面板显示与状态栏一致的处理中文案

## 附加观察项

**建议额外确认**
- 批处理中切换文件时，不会一直停留在“正在处理图片”
- 若导入异常或未知扩展名文件，界面至少应优雅降级，不应崩溃
- 若状态栏已切换媒体类型，日志面板不应仍保留上一文件的错误类型提示
