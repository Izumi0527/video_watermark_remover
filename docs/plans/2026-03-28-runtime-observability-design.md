# 运行模式可观测性增强设计

## 背景

当前视频处理在 `LaMa + GPU 深度修复` 场景下，会因为运行时安全护栏自动从并行模式降级到单进程模式。护栏本身已经生效，但用户在 GUI 和文件日志中无法直观看到“为什么变慢、当前是否仍在正常处理”，容易误判为卡死。

## 目标

在不改变处理结果和运行模式策略的前提下，补齐以下可观测性能力：

1. 在开始处理时显式提示“请求模式 / 实际模式 / 限制原因”
2. 在详细进度区持续显示当前实际运行模式和护栏提示
3. 在单进程长任务中按周期输出心跳日志，证明处理线程仍在推进

## 方案

### 方案 1：只补文件日志

- 优点：改动最小
- 缺点：GUI 仍然缺乏模式解释，用户体验提升有限

### 方案 2：进度区 + 日志面板 + 启动状态统一提示

- 优点：用户能同时在顶部状态、日志面板和详细进度区看到一致信息
- 优点：能清楚区分“自动降级导致变慢”和“程序卡死”
- 缺点：需要同时改动 UI 展示和运行时日志

### 方案 3：额外加入阻塞弹窗

- 优点：最不容易遗漏
- 缺点：会打断单文件与批处理体验，不适合本次范围

## 结论

采用方案 2。

## 设计要点

1. 为运行模式和护栏原因提供统一的中文文案构造函数，避免 UI 和日志各自拼文案。
2. `SignalHandler` 在启动处理时立即向状态栏、日志面板和详细进度区推送运行模式快照。
3. `DetailedProgressWidget` 新增运行模式摘要与提示区域，持续展示请求模式、实际模式和护栏原因。
4. `single_process.py` 增加周期性心跳日志，输出当前帧、进度、处理速度、预计剩余时间和当前运行模式。
5. 所有改动只增强可观测性，不改变现有运行模式决策逻辑。
