### 2. 代码坏味道识别

#### 🦨 识别出的7种代码坏味道

1. **僵化性 (Rigidity)**
   - `main_window.py` 882行，任何UI修改都牵一发动全身
   - 组件间耦合严重，修改成本极高

2. **冗余性 (Redundancy)**  
   - 多个测试文件分散（test_mvp.py, test_phase2.py, test_phase3.py）
   - UI组件代码重复，缺乏统一抽象

3. **循环依赖 (Circular Dependency)**
   - UI组件与业务逻辑混合，形成隐式循环依赖

4. **脆弱性 (Fragility)**
   - 单一文件承载过多职责，易出现级联故障

5. **晦涩性 (Obscurity)**
   - 缺少模块级别的文档说明
   - 业务逻辑与UI展现混合，意图不明

6. **数据泥团 (Data Clump)**
   - UI配置参数分散，应组合为配置对象

7. **不必要的复杂性 (Needless Complexity)**
   - 过度耦合的GUI组件设计

### 阶段3: 依赖注入重构

#### 3.1 服务容器设计
```python
# app/core/container.py
class ServiceContainer:
    def __init__(self):
        self._services = {}
        self._setup_services()

    def get(self, service_name: str):
        return self._services[service_name]

    def _setup_services(self):
        self._services['config'] = ConfigService()
        self._services['logger'] = LoggerService()
        # ...
```

#### 3.2 依赖解耦示例
```python
# 重构前 - 紧耦合
class MainWindow(QMainWindow):
    def __init__(self):
        self.ai_handler = AIHandler()  # 直接依赖

# 重构后 - 依赖注入
class MainWindow(QMainWindow):
    def __init__(self, container: ServiceContainer):
        self.ai_service = container.get('ai_service')
```
